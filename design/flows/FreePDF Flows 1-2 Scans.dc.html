S1 — spec

Order, top to bottom app bar (title Scans, 52 px min height, hairline under, trailing Button ghost “New scan”) · scrolling area, screen padding space-4 · EmptyState centred in it with icon, title, body and action = Button primary “New scan”. No footer, no tab bar, no settings.

Spacing EmptyState’s own steps: icon to title space-3, title to body space-2, body to action space-4. The block is centred vertically in the scroll area, so it stays centred at large text sizes instead of being pinned.

Why the action appears twice the bar action is the one that is always in the same place across the whole app; the one in the empty state is the instruction the sentence just gave. Both are the same words, both go to the camera on Page 1.

VoiceOver bar: “New scan. Photograph the pages of a new scan.” · empty state: title and body are read as text, not as controls · action: “New scan. Photograph the pages of a new scan.”

Large text and German nothing is fixed height; the body wraps and the block grows downward, the bar action wraps to two lines before it truncates. “Neuer Scan” is shorter; “Noch keine Scans” fits.

S2 — spec

Order app bar · ErrorLine as the first thing in the scroll area · space-4 · the S1 empty state, which does not change. The error line pushes the block down; it never overlays it and never becomes a dialog.

Copy the engine’s own sentence, printed unchanged. Shown here with the storage one. Cleared on the next reload — there is no dismiss control, because a control would imply the app decided something.

VoiceOver the line is announced once as an alert when it appears, then sits in the reading order above the empty state. The empty state’s action keeps its label — the failure does not disable it, tapping again is the retry.

S4 — spec

Built from ScanRow with swiped — the 96 px Delete action (--swipe-action-w) is already part of the component; the rest of the list is untouched ScanRows. No screen padding on the list: rows are full bleed so the hairline and the swipe action run to both edges.

Order app bar · rows, newest first, one hairline between each. The swiped row keeps its title and subtitle readable — the action slides in, the row does not shrink its type.

Behaviour the swipe reveals; the tap on Delete opens S5. Nothing is deleted from the swipe alone, and a swipe on another row closes this one.

VoiceOver row: “11 Aug 2026, 20:14. 40 pages, PDF ready.” with the actions rotor carrying “Delete this scan”. The swipe state itself is not announced — the action is, which is what a screen-reader user needs.

S5 — spec

Built from ConfirmDialog (the one raised surface: surface, radius-lg, shadow-lg) over the list, on the scrim of neutral-900 at 38%. The list stays legible behind it, so it is clear which screen you are on.

Order inside the dialog title (h4, Cormorant 600) · space-2 · body · space-4 · the two actions right-aligned in one row, space-2 apart: Button destructive “Delete scan”, then Button secondary “Cancel” — the delivered component’s own order, unchanged. The row wraps before either label truncates, which is what German needs.

No red the destructive button is accent-700 in light, accent-300 in dark, and carries the double rule — border plus inset ring — so it is a different shape from the Cancel below it. The body names what goes: pages, the PDF, the photos.

VoiceOver dialog: “Delete this scan? 40 pages, the PDF and 40 photos go. This cannot be undone.” · confirm: “Delete scan. Deletes the scan, its PDF and its 40 photos.” · cancel: “Cancel. Keeps the scan.” Focus lands on the title; Cancel is the escape.

Counts are real both numbers come from the row that was swiped — a 1-page scan reads “1 page, the PDF and 1 photo go.” Confirm the singular German wording exists in the copy tables; I did not invent one.
